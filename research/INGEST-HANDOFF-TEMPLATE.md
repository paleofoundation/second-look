# Research batch handoff template — not an approved plan

Copy into `research/batches/<batch-id>/HANDOFF.md` and fill with actual records. Keep raw papers outside Git. Read `docs/RESEARCH-INGEST.md` first.

## Operation and checkpoint

- Batch ID, date, researcher, integrator, branch and base Git commit:
- Last accepted checkpoint/version and evidence of acceptance:
- Actual completed scope and next safe action:
- Remaining drug / condition / question / source counts and unresolved work:
- For condition roundups: condition search protocol/cutoff, candidate discovery and dispositions (including drugs outside the initial portfolio), accepted synthesis coverage and unfinished candidates; separate searched, extracted, appraised and synthesized counts:

## Plan before work

- Plan and machine-readable schema paths, versions and SHA-256 hashes:
- Scope, restrictions, targets, coverage and source/identity inventory:
- Worker-readable input locations and verified access:
- Search/query/source and delivery contract; Q01–Q15 and mechanism input mapping:
- GP Plan decision, actual timestamp, scope and check evidence (default HOLD until checked):

## Receipt and preservation

- Actual delivered manifest, filenames/hashes, rights and source-access gaps:
- External-worker reverse ingest prompt, if applicable:
- Accepted / duplicate / excluded / context / inaccessible / unreadable / pending reconciliation:
- Stable IDs, aliases, study families and existing reviewed material preserved:
- Correction/retraction/quarantine and missing-data states:

## Candidate merge and verification

- Candidate output/diff and current-main reconciliation:
- Result, claim, synthesis, review and page mappings:
- Source/numerical audit, schema/relationship validation and idempotent re-import results:
- Actual build/content/rendered/payload tests and version:
- Integrator PASS / FAIL / HOLD with reasons, separately for technical, scientific and release scope:
- Changed evidence and dependent acceptance reopened:
- Rollback/recovery checkpoint:

## Durable rules and next handoff

- New owner instructions or confirmed rule corrections and exact source/date:
- Updated contracts and docs/RULE-CHANGELOG.md entry:
- Pending upstream rule synchronization:
- External access dependencies and next responsible person/action:

Do not fill unknowns with invented values. This file remains a template until a researcher records an actual operation.
