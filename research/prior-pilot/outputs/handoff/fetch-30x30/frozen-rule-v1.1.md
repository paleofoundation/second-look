# The One Match Rule

Version 1.1 · 8 October 2026 · Portable master instructions

## What this rule means

When I say **“Examine site for [topic]”**, **“Pepsanon-style website for [topic]”**, or **“Use the one match rule for [topic]”**, treat that sentence as a request to execute the complete research-publishing workflow below. The topic is the variable; the method should not have to be explained again.

Build an original, useful, source-traceable evidence website with the depth, reading experience, and operational discipline developed for PepsAnon. The deliverable includes the research system, demand map, acquisition prompts, reusable page architecture, functioning account experience, business plan, and quality controls. A landing page, a few sample articles, or an unexecuted plan alone does not satisfy this request.

This is a reusable user instruction, not a claim to override system instructions or platform permissions. My current explicit instructions take precedence over these defaults. Apply this rule to the requested evidence website; do not apply it to unrelated websites or silently change an existing site's identity, audience, or hosting.

A request to write, inspect, revise, install, or export this rule is documentation/setup work. Do not launch a website or its work chats merely because a trigger sentence is quoted in that request.

**Origin:** This rule consolidates PepsAnon conversations and source contracts, the later EMF Mission Control workflow, and relevant longevity-site instructions. Added operating improvements are identified in the companion source audit. Historical page counts, study totals, people, domains, and prices are examples, not facts to copy to a new site.

## 1. Start from one sentence

Infer and record the topic, likely audience, central reader decisions, domain boundaries, available source material, and a working site name. Make reasonable reversible decisions and begin. Do not make me fill in a questionnaire about colors, menus, post types, study fields, or monetization before doing useful work.

Default audience: curious, informed non-specialists, with deeper methods and source detail available to clinicians and researchers. Explain unfamiliar terms without diluting scientific meaning.

Default first priorities:

1. Establish Mission Control and a durable project brief.
2. Discover and organize the real questions people ask.
3. Produce a filled, copy-ready Grokbot acquisition prompt early.
4. Build the shared site and post templates while evidence collection runs.
5. Ingest, verify, synthesize, and publish only the declared scope that passes its gates.
6. Deliver the account experience, monetization plan, and maintainable update process.

If the name, palette, author, scope, deployment audience, merchant, or source access is already known, reuse that information accurately. Choose a provisional name and two-color brand when they are absent. Leave authorship unassigned until a real assignment is known. Do not invent credentials, biography, ORCID, domain ownership, a medical reviewer, or investigator approval.

Use the user's requested model/settings where available; do not bake a model name or unsupported speed promise into this rule. State meaningful assumptions briefly. Ask only for information that materially blocks work, and continue independent work while waiting. A missing merchant account does not block research, design, or the business plan.

### Required first handoff

Before a large build becomes opaque, show the working name, audience, scope, main/accent colors, planned post types, first research priorities, Mission Control status, and filled Grokbot prompt or its location. Distinguish work already executed from work merely commissioned. Give a realistic scope-based estimate; a large literature review is not a five-minute website task.

## 2. Mission Control and work chips

Use the current coordinating chat as **[Site] — Mission Control**. If the environment can create a separate coordinating chat and that is requested, create it and link it. Do not duplicate an existing controller. Maintain a durable `mission-control.json` or equivalent board that survives chat context loss.

Mission Control owns scope, priorities, contracts, dependency order, acceptance, integration, and release. Workers return evidence; they do not declare their own acceptance or independently publish a competing version. One integrator owns the canonical site checkout and deployment.

Prepare distinct work chats/packets for:

| Workstream | Required result | May start when |
|---|---|---|
| Demand | Reddit corpus, question clusters, priority map, exclusions | Scope is drafted |
| Literature | Filled Grokbot brief, primary/context packs, access gaps | Initial topic IDs exist |
| Ingest | Validated canonical records, identity map, extraction provenance | Schema work immediately; live import after acquisition reconciliation |
| Experience | Brand, navigation, shared post shells, sidebars, responsive behavior | Post-type contract exists |
| Answers | Cited guides, FAQs, evidence synthesis, glossary links | Relevant question and evidence records are accepted |
| Study reviews | Universal-question appraisals, citation previews, full reviews, claim links and review versions | Source identity/access reconciled; calibrate diverse examples before scaling |
| Accounts | Real login, private saved library, notes/preferences where supported | Identity and persistence path is verified |
| Business | Audience/offers, guide product, launch economics, fulfillment plan | Initial demand map exists |
| Review | Independent source, content, UX, account, and release checks | Relevant deliverables exist |

For large topics, split Demand and Literature into bounded topic batches under stable IDs, with one shared schema. Do not create dozens of nearly identical chats before they have useful work.

Where the host supports task creation and the user has authorized those work chats, create them and return their actual links. Otherwise, emit clickable follow-up chips that explicitly request a separate task, with a self-contained prompt or a real attached packet. In Codex, use supported artifact follow-up chips. In other hosts, use their native equivalent or clearly labeled copyable prompts. A displayed chip is an invitation; it is not a running task. Never claim a chat, automation, background worker, or Grokbot job exists without a successful operation.

Use subagents for independent work during the active build when available. Code workers use isolated checkouts or nonoverlapping ownership. Research workers write their own output batches. All workers receive the current shared contract, source version, output location, prerequisites, acceptance criteria, and return destination.

### Worker packet contract

Every packet contains: site/topic; exact task; scope IDs; input references accessible to the worker; source version; allowed output location; dependencies; concrete deliverables; evidence requirements; checks; stop conditions; and return instructions. Never rely on a worker remembering another chat.

Every handoff contains: completed scope, artifact links/paths, source/code version, criteria-to-evidence mapping, tests and results, unresolved gaps, conflicts, and a proposed status. Mission Control records its own dated **PASS**, **FAIL**, or **HOLD** with reasons. HOLD means missing work/prerequisite; FAIL means an observed defect; PASS applies only to the inspected scope and version. Preserve prior decisions. Any relevant artifact change invalidates its dependent acceptance until rechecked.

## 3. Find the questions before choosing the articles

Reddit supplies demand signals and reader language. Scientific sources supply the answers. A popular claim is not evidence of efficacy, harm, causality, sales volume, or prevalence.

Create a real question-discovery protocol, not a paragraph saying “research Reddit.” Start with broad topic searches and reader decisions, then expand neutral synonyms, concerns, misconceptions, comparison questions, and community vocabulary. Include both enthusiastic and skeptical communities, general-interest communities, and relevant specialist communities. Record inaccessible sources and sampling bias.

Use a declared recent window, normally the previous 24 months, plus a separately reported historical window. Record the actual execution date, cutoff, exact queries, search surface/API, filters, sort, returned URLs, and zero results. Use permitted public access; do not bypass access blocks.

For retained threads record canonical URL/ID, subreddit, actual post date if available, retrieval date, access status, paraphrased question, decision context, query family, topic IDs, and duplicate/crosspost cluster. Store engagement only when observed; unknown values remain null. Do not collect usernames or create health profiles. Avoid copying entire discussions.

Exclude or separately label vendor promotion, recruitment, bots when evident, affiliate material, unrelated homonyms, duplicates, and removed posts without recoverable questions. Keep an exclusion log. Missing metadata must not silently turn a search snippet into a verified thread.

Cluster questions by what a reader needs to decide. Distinguish intervention, condition, outcome, population, formulation/route, comparison, safety, interaction, quality, cost/access, and practical use. Keep overlapping clusters linked rather than counting them as unique people.

### Priority method

Aim for **40 meaningful question clusters** by default. For a narrow topic, deliver fewer with an explanation rather than inventing demand. This is an editorial research target, not a claim of Reddit-wide “top 40.” PepsAnon's 30 peptide and 30 stack pages are a topic-specific precedent, not a universal page quota.

Use a transparent reproducible initial score: `2 × independent question-thread clusters + distinct relevant subreddits`. Report recent and historical counts separately. Validate the top priorities by direct inspection where possible. Compare the ranking after excluding historical threads and after removing the largest contributing subreddit. Keep urgency, unmet evidence need, and editorial importance in separate fields rather than secretly altering the popularity score.

For a topic labeled demand-validated, seek at least two independent question-thread clusters and two communities, or record a justified niche exception. A vital safety topic may be included as an editorial priority without pretending it is popular. If access is poor, mark the ranking provisional and retain the exact evidence available.

For each topic produce: stable ID; neutral user question; reader decision; source links; demand status and counts; synonyms; proposed page type; intended canonical page/section; related topics; scientific scope; paper-search brief; direct/indirect evidence needs; and current answer status. Maintain a coverage matrix from question → search brief → records → claims → page/FAQ → product opportunity.

Continue open discovery until two successive bounded batches add no material question category, or a declared access/time limit is reached. Report within-protocol saturation or incomplete discovery accurately. Do not delay all work indefinitely seeking impossible proof of exhaustiveness.

Public community collections show useful questions, concise research focus, relevant guides, and original discussion links. Keep scoring, internal priorities, worker instructions, and research-management fields in Mission Control. Label community links **Discussion** and keep them out of primary-study counts.

## 4. Give Grokbot an executable literature assignment

Generate a fully populated version of the prompt in Appendix A. Fill the topic, current dates, scope, topic IDs, synonyms, exclusions, output schema, and topic-by-topic retrieval briefs. Do not hand me a generic prompt full of placeholders I must design myself. Provide it early enough that my Grokbot can work while the site is being built.

For a broad subject without defensible specific candidates yet, begin with neutral seed questions and an explicitly labeled **scoping acquisition brief**. That brief must tell Grokbot how to discover candidate entity–question pairs and return the source-backed shortlist; it must not invent a list of popular or effective drugs. In the same workflow, turn the observed candidates and demand map into the full topic-specific retrieval packet, preserving IDs and logging scope revisions. Initial scoping is an intermediate handoff, not completion of the final acquisition brief. Continue design, schema and account work while this dependency resolves.

Keep two source collections: **PRIMARY** for original eligible research and **CONTEXT** for reviews, guidelines, regulatory information, methods, and other context. Discovery may use reviews for reference chasing, but review papers do not become original studies. A registry entry, protocol, supplement, and published report can describe one study; model those relationships.

Search relevant primary indexes, trial registries, publisher pages, and lawful repositories. Log translated database queries. Include positive, null, negative, contradictory, safety, replication, discontinued, and unpublished/registry evidence when discoverable. Search backward and forward from key studies. Do not restrict discovery to free PDFs or a convenient fixed number of papers. Report language and access gaps.

Separate human randomized trials, other human studies, animal, cell/ex-vivo, engineering/modeling, preprints, and secondary context. Preserve intervention identity, route/formulation, dose/concentration, duration, comparator, population, outcome, and timing. Component evidence is not evidence for a combination. In-silico plausibility is not clinical efficacy.

Maintain two independent status dimensions:

- **Processing:** discovered → identity checked → abstract read → full text acquired → extracted → audited → synthesized → published.
- **Scientific assessment:** not appraised, then documented outcome-specific certainty/risk-of-bias judgments where actually performed.

Also track editorial/human review separately. A named investigator is not a completed review. A full-text PDF is not a completed appraisal. A passed import is not a medical endorsement.

## 5. Ingest evidence without losing identity or provenance

Inspect the incoming archive/manifest before changing public content. Keep raw source files immutable, compute hashes, preserve filenames, and store normalized outputs separately. Validate files as real readable PDFs; detect HTML downloads, corrupt/scanned PDFs, extraction failures, and missing supplements. Use page-aware extraction and visually verify tables/figures supporting important numeric claims. An extraction tool returning text is not proof of accurate extraction.

Distinguish **discovery mode** from **closed-packet ingestion**. If the user limits a task to supplied files or prohibits browsing, read the packet README/RULES, manifest, and gap notes, then every obtained eligible PRIMARY file. Do not fill gaps from the web or model memory. Say NOT IN CORPUS for information absent from that packet; that does not mean absent from the literature. Keep additional input collections separate until identity and scope reconciliation. Gap notes and paywall-needed lists are leads, not study results.

Every received eligible full text must receive substantive page-located extraction or an explicit pending/failure state. Track counts acquired, extracted, verified, mapped, synthesized into answers, previewed, and published. Do not stop at a searchable bibliography when the request is to ingest into the website. Process bounded accepted batches into actual page prose while continuing the remainder. The 10% audit sample below is never a 10% extraction target. Start an unfamiliar extraction workflow with a varied calibration batch, normally 20–30 documents, then scale after errors and applicability checks pass; the pilot is not a literature ceiling.

Use canonical paper identities: normalized DOI first, verified PMID/other identifiers, then exact normalized title when DOI is missing. Do not automatically merge different DOI identities or fuzzy-match shortened titles. Resolve shortened titles with an explicit audited alias map. Track a separate **study-family ID** to associate multiple reports from the same trial/cohort without deleting those reports.

On repeat import, preserve stable IDs and previously reviewed editorial material. An unchanged pack must be idempotent. Reconcile totals as received, accepted, duplicate, context, excluded, unreadable, missing, and pending; no silent losses. Reconcile references against actual obtained files. Records without full text stay useful but accurately marked.

### Portable minimum data contract

Use UTF-8 JSON/JSONL and a declared schema version. Equivalent database tables are acceptable if they preserve these relationships and can export them.

Create and deliver a machine-readable JSON Schema (or equally explicit typed schema) before worker ingestion starts. Specify required fields, types, enums, null reasons, source-locator objects, stable-ID relationships, and at least one illustrative valid record. Validate worker files and cross-record references against it. The table below is the minimum semantic contract, not a substitute for machine validation. Schema examples must be clearly synthetic and excluded from production evidence.

| Entity | Required information |
|---|---|
| Topic | ID, question, scope, aliases, demand provenance/status, intended page, search brief |
| Search | ID, database, exact query, time, date range/filters, hit count if observed, exported IDs |
| Screening | candidate, search IDs, decision, reason, reviewer/time, duplicate mapping |
| Paper | stable ID, title, authors, year/journal, DOI/PMID/PMCID as available, type, language, URLs, rights, filename/hash, access and processing status, corrections/retractions, study-family ID |
| Study | stable ID, related paper IDs, design, recruitment, population/species, total and arm sample sizes, intervention/exposure, comparator, duration/follow-up, outcomes, attrition, funding/conflicts, limitations |
| Result | study ID, endpoint, population/arm, timepoint, estimate type/value, units, numerator/denominator, uncertainty interval, adjustment set, exact source locator, extraction basis |
| Claim | proposed sentence, topic, result/source IDs, exact locators, scope, interpretation limits, verification/review state |
| Context | source type, title, URL, date/version, jurisdiction where relevant, role; excluded from original-study counts |
| Page | stable ID/slug/type, question IDs, structured sections, claim IDs, citation order, relations, author/reviewer assignments, search/review dates |
| Coverage | per-topic search status, independent studies by design, access gaps, direct/indirect findings, unanswered questions |
| Manifest | schema/version, cutoff/execution date, file counts/hashes, reconciliation, completeness and exceptions |

For every extracted value, preserve the source paper, file, PDF page and printed page when different, table/figure/section, and extraction basis (`full_text`, `abstract`, `registry`, etc.). Missing values use null with `not_reported`, `not_extracted`, `not_accessible`, or `not_applicable`; these are different states.

Record reported outcomes and limitations faithfully. Distinguish percentage change from percentage points; relative from absolute risk; within-group from between-group change; adjusted from unadjusted estimates; sample randomized from sample analyzed; association from causation; surrogate outcomes from clinical outcomes. Do not manufacture precision, convert animal dosing into user advice, or create pooled effects without a documented synthesis.

Before publication, verify every public numerical claim against its source and denominator. Inspect all identity mismatches and surprising findings. Audit at least a random 10% of the remaining full-text extractions plus every study supporting launch answers. Any material error expands review across the affected batch. Automated validation covers every identifier, foreign key, required field, and source link that can be checked.

Check corrections/retractions against authoritative records and log when checked. A retracted source remains traceable with its status, is removed from supportive claims unless explicitly discussing the retraction, and triggers affected-page review.

Keep copyrighted raw papers private unless redistribution rights permit publication. Prefer original links and concise lawful excerpts with locators. Never infer a redistribution license from access to a PDF.

## 6. Build a knowledge structure, not disconnected articles

Use a canonical graph connecting topics, interventions/entities, conditions, outcomes, populations, combinations, studies, claims, terms, guides, and questions. Choose public route names appropriate to the subject. Do not call drugs “peptides” or force every topic to have stacks.

Core public surfaces:

- A simple, search-led homepage and clear starting routes.
- Entity/topic directory and detail guides.
- Question directory and concise answers embedded in relevant guides; dedicated question pages only when they add value.
- Research/source library with searchable, filterable canonical study records.
- Glossary with deep, useful term pages and contextual links.
- Comparisons/combinations where scientifically and editorially relevant.
- Practical consumer guides with free preview and genuine paid-product path when ready.
- Methodology, editorial standards, author/investigator profiles, corrections/contact, privacy, terms, and educational disclaimer appropriate to the product.
- Login, account/profile, saved library, and protected purchased resources where applicable.

Group navigation and search results by post type. Search should understand aliases and connect questions to relevant entities, guides, studies, and glossary terms. Provide useful empty states and clear filters. Return stable canonical links rather than placeholder routes.

Give glossary links space in the main navigation, megamenu, and footer. Explain repeated scientific terms at the point of use; avoid excessive repeated links in a paragraph. Add reciprocal “related” links and backlinks from evidence to the questions/guides it supports. Keep related content relevance-based rather than a random card feed.

Derive the glossary inventory from recurring terms in actual content and the reader's questions. Support definitions and source-dependent factual sentences with cited papers or appropriate authoritative definitions and locators. Preserve scientific wording when adding links; avoid self-links and false aliases. The PepsAnon profile caps each paragraph at two distinct related-guide targets and three glossary terms. Curate bounded megamenus independently of library size: PepsAnon used 15 featured entities and 15 combinations in three desktop columns of five, with full-directory links; adapt the featured set to the new domain without hiding the larger library.

Do not publish thin duplicated question pages purely for SEO. One canonical answer can appear in an accordion and be linked from the question index. If a full answer page is warranted, define canonical ownership and keep source/version consistency.

## 7. Universal sidebars by post type

Implement one shared article shell with typed post configuration. Define section IDs, display labels, required data, right-rail modules, and responsive behavior once per post type. New content must inherit the contract automatically. Never repair dozens of pages one by one.

**Left rail:** stable section order, active section, collapse/expand, working deep links. Sidebar labels are single words without punctuation, including nested and mobile entries. Full article headings may be descriptive. For example, “Forms & dosing” has sidebar label “Dosing.” Disclosure icons are separate controls, not part of the label text.

**Center:** readable article width, continuous cited overview, substantive prose, question accordions, outcome evidence, one canonical Research section, then related resources where appropriate.

**Right rail:** save action; relevant scope/facts; actual evidence/review status; related entities/questions/guides/terms; methodology link. Use only modules that help this page. Do not put private notes in public rendered HTML or a shared cache. Avoid redundant summaries and giant promotional panels.

| Post type | Left labels in order | Distinct right-rail data |
|---|---|---|
| Intervention/entity | Overview, Benefits, Safety, Contraindications, Interactions, Dosing, Results, Quality, Status, FAQs, Evidence, Connections, Research | Exact entity/form/route, relevant populations/outcomes, related entities, evidence scope, save |
| Combination/stack | Overview, Ingredients, Rationale, Benefits, Safety, Dosing, FAQs, Evidence, Connections, Research | Component links, exact-combination versus component evidence, related combinations, save |
| Condition/outcome | Overview, Options, Evidence, Safety, Comparisons, FAQs, Connections, Research | Population, outcome definition, studied options, related questions/terms, save |
| Question/answer | Answer, Context, Evidence, Limits, FAQs, Research | Exact question scope, direct/indirect evidence, parent guide, sibling questions, save |
| Study/report | Summary, Methods, Results, Limits, Sources | Design, population/species, year, N, intervention/comparator, DOI/PMID, access/review status, corrections, cite/save |
| Practical/consumer guide | Overview, Evidence, Decisions, Checklist, Limits, FAQs, Research | Audience, scope, version, contents, preview/download or verified purchase, linked evidence |
| Claim/expert watch | Claim, Context, Evidence, Findings, Limits, Research | Exact claim/source/date, speaker's verified role, conflicts if sourced, linked studies, update status |

| Evidence synthesis/comparison | Question, Methods, Studies, Findings, Bias, Gaps, Sources | Protocol/cutoff, eligibility, independent study count, outcome-specific appraisal, missing full texts |

Research on guides expands into exactly **Studies** and **References**. Topic-specific contracts may replace irrelevant sections—for example, EMF guides need Exposure and Measurements rather than Dosing. Record that decision once, then enforce it consistently. Required but unresolved clinical sections should explain the actual evidence gap; do not silently erase important safety questions. Omit genuinely inapplicable fields.

Directories use filters and library navigation. Homepage, login, checkout, and account screens do not inherit article rails. Long policy pages may use contents navigation only.

At wide desktop widths, use sticky left contents and right context rails below the header, with a comfortable central reading column. At medium widths collapse or relocate a rail before squeezing prose. On mobile provide an accessible “On this page” drawer/disclosure, essential context and save controls, and related material below the article. Do not hide limitations or research access on phones. Verify approximately 320, 390, 768, and 1280px, keyboard operation, 200% zoom, visible focus, touch targets, Escape/focus return, sticky offsets, and print behavior.

## 8. Preserve the final PepsAnon reading contract

### Prose and questions

Write a coherent, cited overview. Ordinary explanations remain visible as prose; meaningful question headings open concise answers inline. Use native or equivalently accessible accordion behavior. Clicking an FAQ question must answer it on the page, not unexpectedly navigate away. Optional deeper-reading links belong inside the answer.

Each answer starts by resolving the reader's question, then gives scope, findings, uncertainty, and citations. Avoid repetitive caveats, duplicated “direct answer” boxes, administrative labels, and filler. The PepsAnon guide profile requires exactly one focused prose paragraph per section, at least three complete sentences and 60 words (normally 60–150), with a one-paragraph overview. Tables, lists of ingredients, metadata, quotations, and references retain their own structure. New short-form post types such as glossary entries may define a different versioned contract; do not silently weaken the established guide profile. If verified material cannot support the required depth, record the gap or a deliberate contract exception rather than generating filler.

Keep enough visible narrative that a reader understands the guide without opening every accordion. The historical 75–85% visible-editorial target is a design heuristic, not permission to reverse the later rule that question-led blocks collapse and ordinary explanations remain open. Reader copy says “Studies in animals,” never “ingested animal papers” or “processed/extracted papers.” Raw PDF filenames remain in internal provenance or deliberate technical records, not normal study lists or source notes.

Keep “not studied,” “not found in this search,” “inconclusive,” “evidence of no effect,” and “evidence of harm” distinct. Do not call a selected-source article a systematic review. Explain ingredient/combination, route, population, and outcome limits where they affect the answer. Study dosing is descriptive research information, not a personalized regimen.

### Evidence versus Research

**Evidence** interprets specific outcomes and their supporting designs/limitations. **Research** exposes the underlying papers. They serve different purposes.

On every entity and combination guide render exactly one shared Research component:

1. **Studies:** one disclosure per canonical paper, combining reviewed findings, limitations, source passages, and all associated PDF records. Show known population/species and year beside the title. Findings and limitations come before technical PDF metadata. Unreviewed papers show clearly labeled source excerpts/metadata, never invented summaries or inferred limitations.
2. **References:** one numbered bibliography, collapsed by default. It is a citation destination, not a second study-summary catalogue.

Do not regenerate separate reviewed-study tables, PDF-record tables, excerpt sections, Records sections, or Community sections on the same guide. Use the same catalogue builder and disclosure renderer in the source library. Outcome evidence tables can retain contextual source dialogs; those dialogs must not replace the canonical inline Studies catalogue.

References and study disclosures automatically open when a citation/fragment targets something inside them, on initial load and repeated clicks. Preserve existing fragments and record IDs with aliases during migrations. Browser back/forward, copy links, and anchor offsets work.

### Citations and counts

Number citations separately for each page, starting at `[1]`, assigned by first appearance in rendered reading order. Reuse the same number when citing the same source again. References, source links, structured data, and previews must agree. Keep canonical IDs independent of display numbers; never use numbering as identity. When editing existing pages, preserve old citation/section destinations with redirects or aliases as needed.

Every source-dependent factual sentence carries a linked superscript citation immediately after its final punctuation. Verify that the source supports every clause; split composite claims when needed. Use precise citations for scientific claims. Display DOI once in the appropriate reference/record area rather than repeating the same metadata in many prose blocks. Keep secondary, regulatory, commercial-identity, and discussion sources visibly classified. Commercial material can establish a marketed name or composition; it cannot establish efficacy. Inspect superscripts in rendered prose and tables at phone widths so they do not collide, wrap awkwardly, or obscure values.

Calculate public counts from the canonical data. Distinguish papers/reports, unique study families, reviewed studies, references, PDF files, answered questions, and merely collected questions. Never hardcode PepsAnon's totals, call every PDF a study, or count one cohort repeatedly across reports. Clickable totals lead to the corresponding filtered collection.

Do not insert arbitrary evidence grades. A certainty label must refer to an outcome, population and intervention, have a documented method, and reflect completed appraisal. Otherwise show “Not appraised” or a specific scope/status. Do not add repetitive grading banners to the homepage or unrelated areas. Keep methods accessible.

When using PepsAnon's simplified editorial display, assessed outcomes use Low / Moderate / High in the Evidence table, with the rationale, original appraisal and scope retained. Do not repeat grade badges below prose, inside FAQs, and in previews. This display is not a claim of formal GRADE, and Low must not conceal the distinction between animal-only findings and human clinical evidence. Keep an explicit Not appraised state. A benefit assessment is not an overall safety rating.

Treat established contraindications, precautions, suspected reactions, theoretical concerns, and missing information separately. Trial exclusion criteria are not automatically clinical contraindications; unreported adverse events do not mean none occurred. Prioritize unresolved safety, contraindication, and interaction questions before polishing less consequential claims.

### Study reviews: connect every important conclusion to an appraisal

Build the reading path **consumer question → guide conclusion → cited study review → original source**. A research library needs original mini-reviews of the papers materially supporting its guide conclusions, not only bibliographic records or paraphrased abstracts. Make the exact result, decisive limitation, applicability to the reader's question, and limits of the marketed claim easy to inspect. “Better than Examine” is an aspiration to test through comprehension and source navigation, not an established superiority claim.

Use one versioned editorial review record to supply three depths: a concise citation preview (starting target 50–90 words), a main study review (starting target 500–800 words), and optional evidence details. These lengths are defaults from the new review plan, not hard quotas or replacements for the focused guide-section contract. A very small report may need less; a complex multi-arm trial may need more. Main reviews use clear grades 8–10 prose and the fixed navigation **Summary, Methods, Results, Limits, Sources**. Distinguish benefit results from harms and keep the main finding and decisive limitation visible before a membership boundary.

Every review answers the following internal questions, combining them into readable public sections rather than fifteen repetitive headings:

| ID | Universal study-review question | Required coverage |
|---|---|---|
| Q01 | What question was actually tested? | Objective, prespecification and the precise claim/outcome addressed |
| Q02 | Who or what was studied? | Human participants versus animals, isolated human tissue or cells; eligibility, setting and recruited/treated/analyzed counts |
| Q03 | What exactly was used? | Molecule/formulation, route, exposure, schedule, follow-up, product identity and co-interventions |
| Q04 | What was the comparator? | Control, allocation, randomization, blinding and timing; state their absence |
| Q05 | What was measured and does it matter? | Primary/secondary/exploratory outcome, instrument, timepoint, clinical versus surrogate endpoint and meaningful-change threshold if established |
| Q06 | How large was the result? | Each relevant arm, numerator/denominator, units, absolute contrast and uncertainty; within-group versus between-group distinction |
| Q07 | What happened to the other observations? | Attrition, missing outcomes, adherence, exclusions, analysis population and experimental unit; repeated measurements are not extra participants |
| Q08 | What harms were sought and found? | Ascertainment method, exposed denominator, follow-up, severity/events/withdrawals and detection limits |
| Q09 | How could the design or analysis mislead? | Applicable bias, confounding, selective reporting, multiplicity, precision and internal inconsistencies with source locators |
| Q10 | Does this apply to the reader or product? | Population, indication, molecule, formulation, route, exposure and endpoint matches/mismatches |
| Q11 | Is this independent evidence? | Cohort/study/experiment identity, overlapping reports, follow-ups and replication search scope |
| Q12 | Who conducted and supported it? | Authors, setting, funding, supplied products and disclosed conflicts without treating funding alone as proof of validity or invalidity |
| Q13 | Is the source current and intact? | Version/preprint status, access, supplements, protocol/registration, corrections/retractions, check dates and unfinished checks |
| Q14 | Which claims does it support or contradict? | Explicit guide/outcome/claim links and supported, indirect, contradictory or unassessed applicability; observed data versus authors' conclusions versus reviewer interpretation |
| Q15 | What should this change in our understanding? | Bounded takeaway, remaining unknowns and the future evidence that could change the guide, without individualized treatment instructions |

Answers carry source locators, authoring provenance and verification state. Extend missingness states with **not yet checked** (`not_checked`) and **not identifiable from this design** (`not_identifiable`); neither becomes a zero, negative result or reassurance. Separate paper, study/cohort, experiment, outcome, claim and review-version identities. One paper can contain several experiments, and several papers can describe the same participants.

Validate exactly one answer for each Q01–Q15, not merely an array of fifteen entries. The production schema must support binary and continuous outcomes, timepoints and multiple arms, plus result/claim/source relationships. A draft-only pilot schema with approval fixed to pending is not a production release schema; add exact-version approval and entitlement-safe public/premium serialization deliberately before deployment.

Apply a versioned appraisal method suited to the design and specific result. Examples to verify against current primary methodological guidance are RoB 2 for randomized results, an appropriate nonrandomized-comparative method, JBI case-series questions for uncontrolled series, and SYRCLE for animal experiments. Cell/ex-vivo reviews require an explicit protocol addressing controls, biological versus technical replication, identity, blinding where applicable and exposure plausibility. ## Appendix C — What “Examine site for drug repurposing” means

This example defines adaptation, not completed research or a preselected list of effective drugs.
